# 73-protocol agent-guided knowledge-base branch

The current behavioral-feedback-v2 lineage is an online 58/5/10 experiment.
S001-S005 and C5 are preserved as its immutable seed. Each later batch is first
generated by one concurrent Harbor job under the preceding checkpoint's pact
and prior-only knowledge base, then analyzed in parallel before one batch-level
reconciliation. Batches contain five protocols (three for S056-S058),
checkpoints are frozen at C10, ..., C55, and C58, and the five-protocol
validation panel is launched asynchronously at every checkpoint. The
ten-protocol test panel remains sealed until validation selects one endpoint.

The target protocol's included primary sources are always authoritative.
Canonical ground truth is a comparison target, not independent evidence, and
the runner never changes it. Knowledge cards are deterministic projections
from admitted training ground truth. A procedural pact changes only when a
source- and trajectory-located agent error supports a protocol-neutral rule
and a separate Codex critic accepts it.

## Runtime stages

For every protocol in one checkpoint-bounded batch, the runner performs these
stages against the same immutable parent checkpoint:

1. Mount the preceding checkpoint's cumulative pact and prior-only GT-card
   catalog, then launch all five target protocols in one Harbor job with five
   concurrent trials. Every protocol in the batch sees identical frozen
   learning state and cannot see another batch member's ground truth.
2. Preserve each raw prediction and trajectory. If complete linked T2/T3 fails
   deterministic validation, permit at most two contract/linkage-only repair
   attempts and preserve every attempt; otherwise perform no repair.
3. Score the resulting prediction with the frozen verifier and preserve its
   observation IDs in a hash-pinned comparison.
4. Run one local Codex adjudicator over the prediction, trajectory, verifier
   output, canonical comparison, and manifest-approved primary sources.
   Substantive observations must be partitioned into consolidated root events.
   One bounded contract-only correction is allowed when the scientific review
   is complete but a label violates the eligibility/action contract; the raw
   output and both transcripts are preserved, and the correction may not alter
   evidence, findings, observation partition, or the pact proposal.
5. Admit learning only when benchmark validity is valid, attribution is agent,
   the claim is source-recoverable, and the finding is a consolidated root
   event. Eligible findings require both source and trajectory locators.
6. If one protocol-neutral pact rule is proposed, run a fresh local Codex
   critic. Accepted rules can select only an existing deterministic control;
   arbitrary executable code is forbidden.
7. Wait for every Harbor trial, adjudication, and critic in the batch. Then reconcile accepted
   proposals once in training order. Exact and conservative semantic-near-
   duplicate rules are collapsed to one canonical active rule; each duplicate
   adjudication remains preserved as supporting audit evidence. Every unique
   rebased pack is hash-pinned and must pass the existing synthetic suite.
8. Deterministically project oligo and graph cards only from canonical
   ground truth, admit `SN`, and freeze a checkpoint when N is a checkpoint
   boundary. Predictions, discrepancies, trajectories, and adjudication prose
   never enter the retrievable knowledge base.
9. Starting at C5, launch the five validation protocols concurrently in a
   detached Harbor executor. Training continues while validation runs. The
   executor writes a durable receipt and v4.5.0 macro aggregate.

The pact is cumulative across batches. All protocol adjudicators in a batch see
the same parent-checkpoint pact, so no protocol gains an order-dependent view
of another protocol in its batch. Only after all analyses finish are unique
rules reconciled into the cumulative pact in frozen training order. A protocol
may contribute at most one protocol-neutral proposal, and a rejected, absent,
or semantically duplicate proposal does not add another active rule.

Training, validation, and the selected final-test checkpoint use the same v3
retrieval contract. A worker first creates a target-source-located query using
a controlled feature vocabulary. The runtime computes the complete
deterministic weighted-Jaccard ranking of every admitted pseudonymous donor
before exposing content. The worker may fetch any distinct subset from any
ranks; there is no donor-count ceiling. The ranking digest, selection rationale,
selected IDs, order, and returned cards are preserved. Same-family information
is diagnostic and does not override similarity order. Donors are analogies,
never evidence for target claims.

## Use of validation scores

Validation is a model-selection panel, not a source of scientific learning.
Neither per-protocol validation artifacts nor macro score changes may alter the
pact, knowledge cards, ground truth, discrepancy attribution, or later training
adjudications. This avoids converting five repeatedly observed validation
protocols into implicit training examples.

After all 12 validation checkpoints have completed, the deterministic selector
ranks them using the equally weighted mean of four macro metrics, with invalid
or missing completions already counted as zero in those means:

- T2 required-family F1;
- T3 molecular-transition F1;
- T3 molecular-state F1; and
- T3 typed-edge F1.

Ties are resolved by fewer invalid or missing completions, then the higher
minimum component, higher overall reward, and finally the earlier checkpoint.
The selector also records checkpoint-to-checkpoint regression flags for
diagnosis. It freezes one primary checkpoint before the test panel is opened.
Only the validation-selected checkpoint runs on the ten sealed test protocols.
The existing compatible C0 predictions remain the fixed baseline comparison;
the other checkpoints remain validation diagnostics and never see test data.

The final lock hash-pins the validation aggregates, selection record, selected
primary checkpoint, every learned checkpoint, and the 120-cell test matrix.

The superseded online-training lineage, in which S002-S008 regenerated T2/T3
with Harbor, is retained as an archive but is not part of this experiment.

Source inspection uses a fast-first policy for the two-day execution budget:
read every listed source once with native/layout text, use a complementary
parser only for missing, ambiguous, or table-heavy passages, and render pages
containing figures, diagrams, or unresolved sequence evidence. Workers should
not spend time inspecting parser/query-tool help or implementation source when
exact commands are supplied, or running redundant whole-document conversions.
This reduces repeated tooling overhead without relaxing source or figure
coverage.

## Authentication and cost boundary

Checkpoint Harbor trials and direct adjudicator/critic calls require the local
`~/.codex/auth.json`. The launchers unset `OPENAI_API_KEY` and
`OPENAI_BASE_URL`, set `CODEX_FORCE_AUTH_JSON=1`, and refuse to start without
the auth file. This prevents silent API-key fallback.

## Operator commands

First create the lightweight C5 fork. It reuses the already hash-registered
task tree and copies only the C5 state required for independent continuation:

```bash
libstruct-libgen-capability-improvement kb-fork-behavioral \
  --source-experiment-root "$OLD_EXPERIMENT_ROOT" \
  --output-root "$EXPERIMENT_ROOT" \
  --run-root "$RUN_ROOT" \
  --repository-root "$REPOSITORY_ROOT" \
  --created-at "$(date -u +%Y-%m-%dT%H:%M:%SZ)"
```

Launch the full resumable loop under a detached supervisor with a durable
running/succeeded/failed receipt:

```bash
libstruct-libgen-capability-improvement kb-launch-loop \
  --experiment-root "$EXPERIMENT_ROOT" \
  --base-config improvement/fixed_panel_harbor_base.json \
  --max-protocols 53 \
  --receipt "$RUN_ROOT/receipts/training-loop.json" \
  --log "$RUN_ROOT/receipts/training-loop.log" \
  --analysis-concurrency 5
```

`kb-run-loop` remains available as the foreground equivalent. Reissuing the
launch command returns the live or completed receipt instead of starting a
second supervisor.

One cycle can be exercised independently:

```bash
libstruct-libgen-capability-improvement kb-run-next \
  --experiment-root "$EXPERIMENT_ROOT" \
  --base-config improvement/fixed_panel_harbor_base.json \
  --created-at "$(date -u +%Y-%m-%dT%H:%M:%SZ)"
```

After C58 training and every validation receipt have succeeded, the primary
endpoint is chosen as one coherent pact checkpoint. Do not splice rules from
different checkpoints by metric. The normal final supervisor pairs that pact
with the complete C58 ground-truth-only catalog, runs one additional
five-protocol validation confirmation, and opens the test panel only if the
composite has zero invalid outputs and ties or beats the original coupled
checkpoint under the same frozen selection ordering. Otherwise it falls back
to the original coupled checkpoint.

The lower-level checkpoint-only lock remains available for historical
lineages:

```bash
libstruct-libgen-capability-improvement kb-select-validation \
  --experiment-root "$EXPERIMENT_ROOT" \
  --created-at "$(date -u +%Y-%m-%dT%H:%M:%SZ)"

libstruct-libgen-capability-improvement kb-lock-final \
  --experiment-root "$EXPERIMENT_ROOT" \
  --created-at "$(date -u +%Y-%m-%dT%H:%M:%SZ)"
```

If a completed validation job contains explicit Harbor infrastructure
exceptions (currently limited to exhausted Docker address pools or an explicit
local-model capacity exit), recover only those cells before selection:

```bash
libstruct-libgen-capability-improvement kb-recover-validation-infrastructure \
  --experiment-root "$EXPERIMENT_ROOT" \
  --max-parallel-cells 5
```

The recovery manifests pin the original receipt and aggregate, the exact
failed cells, and each replacement trial. Scientific invalid completions are
not retried. If a targeted recovery itself reaches the agent watchdog, keep
its completed cells frozen and rerun only the timed-out cell with a larger
agent-timeout multiplier. The final recovery manifest records every attempt,
including its config hash, result root, result hashes, timeout multiplier, and
exception outcome, before atomically replacing the canonical aggregate and
receipt. Test jobs independently allow two bounded retries for Harbor
`RuntimeError` infrastructure failures.

After that checkpoint-only lock, plan and execute only the
validation-selected checkpoint on the sealed test panel. The ten protocols run
concurrently and write one durable receipt and aggregate:

```bash
checkpoint="$(jq -r .selected_checkpoint "$EXPERIMENT_ROOT/validation_selection.json")"
libstruct-libgen-capability-improvement kb-plan-evaluation \
  --experiment-root "$EXPERIMENT_ROOT" \
  --checkpoint "$checkpoint" \
  --panel test \
  --base-config improvement/fixed_panel_harbor_base.json \
  --created-at "$(date -u +%Y-%m-%dT%H:%M:%SZ)"

libstruct-libgen-capability-improvement kb-execute-harbor-plan \
  --plan "$RUN_ROOT/plans/evaluation/$checkpoint/test/plan.json" \
  --run-kind test \
  --receipt "$RUN_ROOT/receipts/test/$checkpoint.json"
```

The loop is resumable from `experiment.json`. It never repeats a frozen
microstate, baseline-trial hash, comparison, adjudication, or completed
validation receipt. Reached checkpoints are reconciled on every resume so a
crash between state admission and validation launch cannot skip a panel.
Post-C5 adjudication runs in checkpoint-bounded parallel batches; pact
reconciliation remains deterministic and happens only after a complete batch.
Validation uses the frozen design concurrency and overlaps later batches.

The complete post-training gate can be launched before training finishes. Its
detached supervisor waits for S058 and all 12 successful validation receipts,
freezes the checkpoint selection, constructs and confirms the selected-pact +
C58-KB composite, records the effective endpoint in the final lock, and then
runs exactly one concurrent ten-protocol test job:

```bash
libstruct-libgen-capability-improvement kb-launch-final-replay \
  --experiment-root "$EXPERIMENT_ROOT" \
  --base-config improvement/fixed_panel_harbor_base.json \
  --receipt "$RUN_ROOT/receipts/final-replay.json" \
  --log "$RUN_ROOT/receipts/final-replay.log" \
  --composite-final-kb
```

The composite endpoint and confirmation records pin both checkpoint hashes,
the C58 catalog, both validation aggregates, and the pass/fallback decision.
Consequently, a successful test aggregate cannot be misreported as an
unmodified historical checkpoint.

Run receipts and cycle records live in the configured private run root. Source
bundles, ground truth, adjudications, knowledge cards, and checkpoints remain
in the private audit-data repository. Only pipeline code, schemas, tests,
generic runtime files, and this documentation live here.
